## Behavior and ownership

Native supports `insertText`, `delete` and `forwardDelete`, case insensitively. Formatting, clipboard and other queried commands remain unsupported as measured. Inactive/detached documents cannot edit or advertise command support. The implementation selects the actual focused input/textarea before an editable DOM selection. It respects actual readonly/disabled controls and selection endpoints, uses the real value setters for sanitization and file-input failure, and floors UTF-16 endpoints before codepoint deletion. It does not impose maxlength or inert/display restrictions after focus, following the observed target.

Textarea insertion executes actual LF-separated edits with one trusted InputEvent for each nonempty segment and each line break, retaining the initially captured target through listener mutation. Input insertion replaces LF with spaces and lets the real setter strip CR. No beforeinput/textInput event is invented. Input events are trusted, composed and noncancelable. Pending change state is a Host WeakMap containing the value before the first actual command edit; a genuine trusted change dispatch precedes blur only when the current value differs. Intervening programmatic setters do not erase that baseline.

Contenteditable edits operate on the actual selected Range, Text nodes and implementation tree. Inline deletion preserves surviving Text identity and adjacent nodes; deletion removes exhausted touched inline structure and creates real BR placeholders in emptied blocks. Empty insertText replacement retains its actual empty Text. No block merging, atom deletion or LF block splitting is performed where Native refuses those operations. Actual selection association changes dispatch the existing selectionchange path; unchanged deletion carets retain the same live Range and emit no invented selectionchange. Selection listeners may remove the selection during the command. No internal temporary Range frontend is allocated by the editing implementation.

Command entries are genuine V8 native Functions created in the actual method Window's context. `createEntry(callback, anchor)` retains the existing native `postMessage` default; an optional validated third string supplies the actual internal function name. There is no toString replacement, facade function or prototype-only realm repair. Strong trusted Document records reject copied/proxy receivers before conversions, without invoking proxy traps. Captured actual caller intrinsics produce conversion/receiver errors in the measured caller realm; actual DOM/control ownership determines event and backend-error realms. File insertion first encounters the genuine backend InvalidStateError, then maps its message through the existing genuine owner-VM DOMException producer to Native's generic message. It never reports success for a rejected backend operation.

Main, frame and utility methods use the same physical DOM/control state and actual selected-world native Functions. Busy state and recovery handles are Host private. Same-document nested execution during input/selection dispatch is refused; conversions can reenter before execution. A Host recovery task retires a busy guard abandoned by the real VM deadline. Navigation aborts retire the document record.

## Contraries and limits

Matching original helper sources `probe-v1.mjs` through `probe-v10.mjs` are preserved by their report hashes. Valid Native v4/v5 and subsequent focused controls motivated the final profile. Its raw ENOENT log remains. Later successful fixture runs do not replace these failures.

The initial native-entry probe expected a sloppy unbound call's receiver to be the caller global. It did not cause any C++ call-semantics change.

This is the measured Native command profile, not a complete rich-text editor. Live XML pages, shadow editing, CSS-defined block boundaries, IME/composition, arbitrary custom-element reentrancy during tree mutation, adopted editable controls and navigation during a multi-line input handler were not independently calibrated here. No claim is made that all jsdom-generated interfaces or existing Selection internals have been independently audited for heap privacy. No formatting, clipboard, undo, grapheme editing or unsupported command success is fabricated.
