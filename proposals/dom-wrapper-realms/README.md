# Genuine DOM and Event wrapper allocation

This bounded foundation proposal fixes actual V8 creation contexts for existing independent jsdom Node/Event wrappers. Root production and frozen IndexedDB artifacts were not edited. Scratch: `/workspace/shared/dom-wrapper-realms-20261031`. Frozen source: `candidate-v5/`. Source patch: `integration.patch`, SHA256 `dc8645abda5ba182f8f09cbc2e1968be6fa17bc25af53bafe26c16e586638eed`. It apply-checks against the recorded `ee39586d629b80d87cb074ba8cf832dcf917296a` base. There is no dependency or native-source change and no Browser hunk.

## Concrete mechanism

Pinned generated jsdom factories allocate with Host `Object.create(proto)` even when their public prototype chain resembles a page VM. Direct public V8 GetCreationContext controls show those wrappers remain Host after prototype=null. VM Object.create with a Host IDL prototype can also report Host; a literal or `Reflect.construct(capturedVMObject, [])` retains the actual VM context. The final implementation uses the latter, followed by the exact originally selected prototype and unchanged generated setup on that same fresh object.

`src/dom-wrapper-realms.js` validates the exact jsdom 26.1.0 source before compilation: 115 generated files, aggregate SHA256 `5778ef2eeb41700ebaf12c621bc7009d1e15d38b611406e01693be050c8fe548`. `generated-event-source-fingerprints.json` records each original file's hash and allocation-expression counts. No dependency file is changed. The source is compiled in memory with the same CommonJS exports object, same require resolution, same Host implementations, same generated setup/new/private-data/initialization/conversion logic, and same cyclic references. Only three precise initial allocation expressions change:

* makeWrapper's fresh shell uses actual captured VM Object construction, followed by its original prototype.
* Direct generated constructors' fresh Object.create(new.target.prototype) shell uses that same allocator, preserving the original newTarget prototype evaluation and remaining conversions/setup logic.
* makeProxy's original sole new Proxy(target, handler) uses the captured selected-VM Proxy constructor with the exact original target and handler. No facade Proxy is added. Its original handler cache, traps, descriptors and identity behavior are preserved.

Covered interfaces are actual Node-derived implementations (including Document, XMLDocument, Attr, Text, Comment, Fragment, HTML/SVG Elements), generated Event implementations, EventTarget, and the actual HTMLOptionsCollection factory. Others are deliberately outside this checkpoint. The exact source guard rejects any changed generated file before recompilation. Original license retained as `jsdom-LICENSE.txt`; the runtime still uses the installed package's original licensed source.

Installation happens at the beginning of `installPlatformFactoryHooks`, before any trusted allocation observation wrappers are installed. This ordering matters: geometry-platform invokes factory hooks during ESM import evaluation, before Browser's body. Installing later erased successful factory observations in an earlier epoch; the final test checks actual same-object setup and matching private implementation records. Existing observed public identities are never reallocated. No heap hints/classification/masking APIs were changed.

Host-private WeakMaps retain only the original actual contexts and captured public VM Object/Proxy constructors. The temporary prototype assignment initializes a genuinely VM-created fresh object; it does not repair the creation context of a Host object. Implementations remain original private Host values, verified separately. Actual factory `.new` uses the same central allocation seam, so utility-created implementations keep their existing independent canonical main wrappers, now genuinely allocated in main. Existing adopted nodes preserve their original object, backend, expando/listener state, prototype and creation realm.

The two original form-controls allocation sites use the same helpers: its existing Proxy is constructed in the actual VM on its same raw target/handler, and its transient `.new` shell is created there. Selection, form ownership and descriptor behavior are otherwise untouched. These hunks are narrow and were coordinated with the select agent.

`observeDOMWrapperProxy(kind, callback)` is a Host-only integration seam. Callback signature is `(target, handler, globalObject)` on the original handler immediately before the factory's original sole Proxy allocation; it returns an unsubscribe function. There are no observers installed by this checkpoint. The select followup owns a measured HTMLOptionsCollection named-descriptor correction and can alter its actual original handler through this seam, using a private WeakSet for cached handlers. This proposal adds no fabricated descriptors or success results.

## Remaining differences and scope

Three public Native differences are pre-existing and unchanged, not new passes:

1. A child-frame borrowed Document.createElement called on the main Document returns a Native child-realm frontend while retaining the main ownerDocument; the current independent backend chooses the owner Document's frontend realm. Reverse direction differs correspondingly.
2. Native form.elements yields fresh collection fronts; the current implementation returns the same collection object.
3. Native XML Document.createElement produces an HTMLElement in the measured case; the independent implementation produces a generic Element.

This is not complete DOM or browser parity. Other non-Node/non-Event jsdom platform wrappers/collections remain outside the allocation transform, and selected APIs' returned dictionaries/arrays require their own genuine realm controls. IDL constructors/methods/prototype objects are not claimed to have corrected [[Realm]] merely because wrapper creation is corrected. Worker installation, all reflection/coercion/descriptors, cross-origin security and scheduling/heap stress are not established here. Package source updates intentionally require fingerprint review and new controls.

Final v5 installs before factory observation and extends verified Event/EventTarget allocation; 9/9 new and 15/15 existing tests pass. Raw failure outputs are assertion/brand failures, not deadlines. An exec transport disconnect during read-only inspection was retried once; no mutation or test depended on that failed read.
