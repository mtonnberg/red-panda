# WebSocket admission and real shared transports

The default CLI/Browser limit is eight actual concurrent WebSocket transport attempts. `--ws-max-concurrent 50` supplies the pinned native test runner's separately measured global configuration. Admission is shared by real Browser ownership across contexts, pages, frames and workers; independent Browser instances have independent controllers. Constructors reserve genuine pending transport attempts. Denied admission creates no network request and reports the measured asynchronous error/close sequence.

Window sockets use the existing generated WebSocket/EventTarget public interface and a genuinely independent private backend using Node's `ws` transport. Physical Worker sockets are owned by the parent Page. Captured private ThreadWorker messages carry transport commands/events; authored postMessage cannot select that channel. Worker exit detaches delivery while preserving the actual still-open socket and quota until remote closure or owning Page teardown, matching measured Native behavior. Immediate Worker connecting cancellation aborts a real pending ClientRequest before upgrade; otherwise a captured Host turn-start message ends the actual upgrade request. Client close retains admission through its actual close listener dispatch; remote closure and failed handshake release before listener dispatch.

`websocket-quota-runtime-root-rebased.patch` is the production delta. The source was independently tested in this scratch graph; Root's newer unrelated modules were not substituted into those test results. Only the Browser import hunk was rebased to preserve Root's new leading imports; read-only git apply --check against Root succeeded. `websocket-quota-runtime.patch` retains the original scratch-base delta. No dependencies or C++ sources changed, so no native rebuild is required.

`service-worker-main-close-test.patch` is separate. The old assertion fails on the pre-quota source as well. A real Native configured service worker becomes active, emits timer fetches, holds an HTTP response, survives main window.close with closed=false, continues timer fetches, and completes that response plus a real follow-up report. The revised assertion retains actual owned Page.close cancellation. Both raw results and the original failing log are retained.

## Limits

This is a bounded transport/CLI improvement, not complete browser equivalence. Existing Window generated wrapper allocation and observable implementation-symbol/receiver behavior are retained; socket/quota/request backing records are private Host WeakMaps. Existing Worker Event/CloseEvent and Blob foundation gaps are not hidden. Standalone Host installers without a Browser receive an independent genuine owner controller and abort cleanup, preserving the supported embedder tests; the CLI uses the real Browser controller.

Proxy behavior, redirect/authentication policy, extensions negotiation beyond the unchanged fixture, exhaustive TLS and blocked-port profiles, long close-reason edge cases, very large frames/backpressure limits, all navigation/GC lifetime combinations, and hostile object conversions need separate Native calibration. Worker transport start is scheduled by a real private Host turn message; this does not claim every network/microtask scheduling interleaving matches Native. Window is on the existing pinned generated EventTarget backend; no global EventTarget rewrite, fake instanceof, captured response replay, or synthetic successful upgrade was introduced.
