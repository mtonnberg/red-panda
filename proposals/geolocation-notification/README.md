# Geolocation denied defaults and Notification/Permissions APIs

`integration.patch` is a narrow adaptation of current Root. It preserves current
Canvas/Storage/CSS/Console installers and leaves `world-sessions.js` byte-identical.
No Root production files were edited by this worker. No dependencies, native
bindings, sensor services or external network destinations are added.

The new Window/frame module creates actual VM-realm interfaces and methods.
Host-only WeakMaps hold geolocation jobs, watch counters, error data and captured
Notification values. Private records are not put on VM globals, public objects,
or implementation symbols. Genuine `GeolocationPositionError` objects have native
code1 and `User denied Geolocation`, rather than Error/DOMException inheritance.
No coordinates or successful sensor positions are generated by default.

Geolocation callbacks run through actual owned tasks and the existing bounded
VM invocation adapter. Watch IDs are positive and advance; clearWatch cancels the
real queued task, releases callback references and never invents a delivery.
Native watches in this default path deliver once. Navigation/final close cancel
owned work, while frame retirement cancels old jobs and preserves new requests
in the original retained realm. Fresh native controls confirm the callback uses
the actual child Window receiver and child error class even for a callback created
in the parent. Options are converted in the measured order before scheduling.

Notification is a genuine realm EventTarget containing captured readonly public
values. It accepts native-observed string/Symbol conversions and preserves the
native `default` permission result. requestPermission returns an actual immediately
fulfilled realm Promise and ignores the optional legacy callback, including a
non-function argument. Native close() produces no automatic close/show/display
events; the implementation preserves that behavior while real authored event
dispatch works. Unknown options such as data/actions remain unsupported.

Existing Permissions statuses remain fresh real EventTargets with prompt metadata.
The patch fixes measured synchronous descriptor reads, Symbol-name conversion and
invalid-argument rejection wording. It also captures the actual TypeError and
EventTarget methods before authored replacements. No permission state is silently
promoted to granted. The existing document-owned promise settlement guard remains;
fine-grained permission-query microtask ordering is not established by these rows.

## Remaining bounds

The default denied/prompt paths are implemented. CDP permission grants, explicit
geolocation overrides, successful position/coordinate production, browser/device
permission changes and real notification presentation are not implemented. Root
continues returning actual `-32601` errors for unsupported grants and overrides;
a focused check verifies they cannot acknowledge a fabricated grant or position.
Notification in dedicated workers, complete utility-world exposure, exhaustive
WebIDL coercions and callback-exception/timing combinations remain unproven or
outside this Window/frame module. No native performance or isolation claim is
made. Port9582 was not used.
