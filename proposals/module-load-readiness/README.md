# Document load must not drain asynchronous module application work

The genuine Native Window control fires DOMContentLoaded/load at17ms with document.readyState complete while its actual1600ms top-level await remains pending until1616ms. Red Panda's module adapter already gives its real document these semantics, but Browser delayed its public load event and default navigation readiness until moduleReady. CDP consequently hid the real completed document behind application work.

The narrow patch publishes the actual root/child load and lets default Browser/frame navigation finish at that document barrier. The existing moduleReady promise still drains actual module evaluation, imports and top-level await. No module loader, timer, fixture, assertion, source deadline or worker implementation changes. Two tests that assert completed module work now explicitly drain moduleReady. Three new real HTTP/Browser/CDP tests verify load while modules genuinely remain suspended, then release those exact modules and verify completion.
