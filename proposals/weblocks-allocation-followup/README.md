# Web Locks allocation followup

This is a narrow followup to immutable `proposals/weblocks`, to apply **after** its original integration patch. `allocation-followup.patch` changes only `src/web-locks.js` and adds `test/web-locks-privacy.test.js`. It intentionally contains no Browser installer change. The frozen original module SHA256 is `4dd0be0e211d392f79db7eb18ad8e8caa4a1a694319267b53cfb98bb0dfd2ddc`.

The original installer retained a VM plain object containing `global`, `makeManager`, `makeLock`, `abort`, `deliver`, and an appended Host `invoke` function. Its Navigator getter had a separate private VM HomeObject. The followup keeps persistent controllers, factories, request/lock records and bridge dictionaries in real Host null-prototype allocations. Brand validation crosses the bridge as booleans; lock getters return primitive fields; requests pass their real public receiver and signal wrapper. The private owner and AbortSignal implementation no longer enter VM helpers.

Actual public managers/locks and snapshot objects/arrays are allocated through captured realm intrinsics and real public prototypes. Public class methods/getters retain their actual public prototype as HomeObject. Navigator's getter uses the existing native entry binding and correct getter metadata. A Host delivery closure executes captured realm Promise adoption within the same single bounded VM invocation as the callback, preserving the old task/microtask boundary. Queue, registration, promotion, abort, steal and retirement algorithms retain their behavior.

The new genuine `queryHeapObjects(Object.prototype)` test keeps an authored factory-shaped lookalike, an ordinary object, an actual manager and held Lock alive. The exact frozen old module fails because both private and authored factory records are visible (actual count 2, expected 1). The revised module passes while every genuine authored/public identity remains visible. No heap filtering, property/name-based runtime redaction, public wire placeholders or native engine imports were added.

Verification ran serially in `/workspace/shared/weblocks-allocation-followup`, composed from a captured current Root source graph plus the original Web Locks installer and followup. `executed-source-hashes.json` records the actual graph; `scratch-browser-adaptation.patch` is provenance only and must not be applied to Root. Native binaries/node_modules/automation were shared by symlink. Focused tests passed **16/16 on Node 24.22.1, 24.19.0 and 26.13.0**, including all unchanged original15. Logs preserve existing MaxListeners warnings. No broad regression or PureScript suite ran for this followup.

Candidate replay through the unchanged frozen helpers matched **37/37 authored JSON-string Native runtime rows**: main16, scope11, callback3, edge7. The original frozen Native records and helper hashes were reused; no fresh Native run was necessary for this private-allocation-only change. Scope's three non-runtime frame/context/target metadata rows are excluded from the37 exactly as before (real candidate UUIDs differ from Native integer IDs). `evidence/comparison.json` gives per-row equality and helper identity. The unresolved Native borrowed cross-realm steal branch that closed CDP is preserved in `native-reused/native-scope-v1.*`; the successful revised helper omits that branch. This does not establish new behavior for it.

Known bounds inherited from original proposal: observed Native document-scoped pools, WorkerNavigator/utility-world Web Locks uncalibrated, Native borrowed cross-realm steal unresolved. This allocation test covers the real Object-prototype query path and persistent factory records; it is not a claim of exhaustive heap privacy across unrelated modules, all inspector function scopes, or arbitrary external mutation of jsdom internals. No runtime deadlines were changed. Root integration/composition regression remains the parent's serial verification step.
