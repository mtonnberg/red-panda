## Actual behavior and ownership

The pinned library is a real in-memory IndexedDB implementation: stores, indexes, keys, queued requests, transactions, cursor iteration and update/delete, auto increment, rollback, and commit use its actual records and algorithms. No fixture results, success counts, or database values are invented. Each actual BrowserContext owns origin-keyed factories. Same-origin frames, navigation, and new targets retain real records; another hostname or BrowserContext isolates them. Opaque-origin access throws a real selected-VM DOMException.

The frontend constructs actual selected-VM IDB classes and EventTarget subclasses. Host WeakMaps carry private records. Borrowed methods reject unbranded/copied/proxy receivers without invoking their traps. Requests remain strongly alive through actual delivery and cursor continuation. Actual trusted events dispatch through jsdom's genuine request → transaction → database EventTarget path; user handlers receive the actual request receiver. Backend event cancellation reflects genuine frontend preventDefault. Thrown request handlers are observed from actual synchronous Window error events and drive the real backend transaction abort and rollback, including when the Window error is canceled.

Graph copying preserves actual cycles, aliases, snapshots, ArrayBuffer/view bytes and sharing, Map/Set/Date/RegExp/Error values, and genuine CryptoKey material. Values returning from the backend are freshly constructed in the owning VM, never repaired by prototype reassignment. Actual Node CryptoKey material is stored by the backend structured clone and reconstructed by Root's private WebCrypto codec; the returned private key can actually sign and verify. Request.result and cursor.value identities, and fresh record/key/range getter copies, follow the independent Native controls. DOMStringList is an actual VM Proxy with a genuine branded VM target and virtual numeric lookup; its public Proxy classification is not concealed.

Native deliberately differs from standard connection blocking: measured open/upgrade/delete bypass live-connection versionchange and blocked events; old connections retain their version snapshot and can continue to access real stores until actual deletion. The adapter removes the pinned backend's connection gate list before these operations, keeping actual database/store records and old connections intact. Deletion clears the actual raw stores before delivering success. This uses documented-in-this-proposal private package fields `_databases`, `connections`, `_rawDatabase`, `rawObjectStores`, `_indexesCache`, and transaction `_state`; the exact package pin is necessary. Index handles use the actual created index in the backend's cache. No backend library source was edited.

Document abort/Window.close disposes actual request listeners, pending roots and database connections. The frozen popup implementation runs a real prepared Page/VM/Document in the same context; its full integration evidence belongs to the popup handoff.

## Historical epochs and bounded gaps

Raw earlier runs are retained. `candidate-fixture-v1` failed due the helper's incorrect working directory before exercising IndexedDB. Initial module-global access exposed Native's nullable global getter receiver, then fixed. Early projection epochs exposed a real lifetime bug: completing the upgrade transaction dropped its open request before success, and reading a cursor request after callback continuation could throw while pending. Both were corrected with real pending roots and pre-dispatch cursor state. `candidate-fixture-v5.json` is an explicit full-fixture negative on the standalone graph lacking Window.open; it must not be called a full fixture pass. `final-r1-projection.txt` is a helper CLI argument error before execution (missing root argument), not a runtime assertion or deadline; corrected run is `final-r1-projection-v2`. There are no final deadline failures. Node test logs include pre-existing Page MaxListenersExceededWarning messages; no warning suppression was added.

This checkpoint leaves non-factory method arities and exhaustive WebIDL argument coercions/error text incompletely calibrated (many method lengths are 0), native exotic-object reflection beyond measured rows, and additional cloneable platform values such as Blob/File/DOMException and boxed primitives. Unsupported platform/exotic objects are explicitly rejected with DataCloneError rather than silently cloned as empty objects. More Native capability controls are needed before expanding them. DOMStringList's real Proxy wire classification can differ from Native. Worker/utility-world IndexedDB installation, disk persistence, cross-process persistence, exhaustive scheduling stress, and broad heap/lifetime coverage are not established here. Context persistence is in-memory and scoped to the actual BrowserContext lifetime. No complete parity claim follows from passing these bounded controls.
