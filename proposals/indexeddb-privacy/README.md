This is a bounded audit of the frozen IndexedDB r1 constructor table and public value allocation. It delivers evidence rather than an IndexedDB source patch: the suspected retained constructor Map was not observed by actual public V8 QueryObjects. The scratch-only Host-lookup draft was discarded, and `/workspace/shared/indexeddb-privacy-20261031` is restored byte-for-byte to its copied r1 graph. The original r1 proposal, Sanitizer proposal and Root production were not changed.

The serial targeted probe used a genuine fresh jsdom VM, the exact frozen r1 backend/frontend, and the existing compiled public-V8 QueryObjects binding. It returned each complete prototype query result, without property/name filtering, factory classification, fabricated counts or substituted values. It first measured the empty VM, then installed the existing shared invocation adapter, then installed IndexedDB. Result arrays have the selected VM's actual creation context.

Actual retained Map.prototype counts were 0 in the pristine VM, 0 after the invocation prerequisite, and 0 after IndexedDB installation. An authored public Map then produced exactly one match with the actual authored identity. A genuine IndexedDB put/get produced a separate selected-VM Map with preserved stored graph data; querying returned exactly the two real public Map identities, and both remained after the transaction settled. The copy was independently mutable. This validates the positive query and real backend path while failing to validate the suspected retained private Map. The factory-local constructors Map is not referenced by retained inner methods in the audited source; a declaration alone did not establish a leak. No unnecessary Host-lookup mutation is proposed.

The probe separately establishes an existing shared invocation issue: WeakMap.prototype counts are 0 before `createInvocationTrampoline`, 1 afterward, and still 1 after installing IndexedDB. The shared invocation bootstrap creates a private VM parents WeakMap and a VM controller retained by its lexical binding. These are in the existing shared invocation.js prerequisite, outside the IDB-local constructor table. This report does not claim that the complete environment is free of private VM helpers. Root was notified of this independently observed count; this slice does not alter the shared callback/timeout adapter.

Direct public-V8 SameRealm and creationGlobal checks cover 17 actual frontend values before and after setting each value's prototype to null, followed by restoring its exact original prototype. Eight values are genuinely selected-VM-created: IDBFactory, its constructor/method, IDBKeyRange, IDBObjectStore, IDBIndex, DOMStringList's actual Proxy, and the returned graph Map. Nine values are Host-created in r1: authored/trusted IDBVersionChangeEvent, open/get/put requests, database values and transaction values. The exact row names and results are retained in before-r1.json. Prototype changes leave every creation result unchanged, establishing the limitation independently of prototype identity or claimed protocol metadata.

The Host-created rows arise through jsdom's original Event/EventTarget generated constructor allocation. The separately owned central DOM allocation work has explicitly expanded to genuine Event/EventTarget and generated Event subclasses. Its owner confirmed that coverage. No per-IDB allocation adapter or prototype workaround was added here; Root should validate those same real IndexedDB paths after composing that central fix.

The narrow heap slot was explicitly coordinated with Root after the candidate455 matrix completed, and was released immediately when this probe exited successfully. The probe uses no server ports, broad/heap-enumeration test suite or PureScript tests. All worker-owned jobs are quiesced. manifest.json pins the Node/native source+binary, IDB source/backend identities, command, source restoration and raw observations. This evidence establishes the stated bounded negative/positive observations, not exhaustive API, privacy, lifecycle or browser equivalence.
