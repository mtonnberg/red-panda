# Promise ownership attribution: static correctness plan

No runtime probe in this directory has run. No candidate exists and no Root implementation is edited. This work is separate from rejected animation checkpoint R3, public callback-boundary experiments and cooperative-provider design.

## Current behavior and concrete challenges to test

`src/errors.js` installs a process-wide init-only Promise hook. At allocation, `owner(resource)` walks up to 32 public prototypes, taking the first registered `window.Promise.prototype`. It eagerly stores `{record, reason:undefined, reported:false}`. Rejection reporting thereafter uses this cached record; later prototype changes do not change an already-attributed Promise.

Consequently a genuine VM Promise changed to a null prototype *after* allocation is a necessary positive preservation control, not itself a demonstrated defect. The real challenges are allocation through a subclass whose prototype chain was changed before construction, a proxy in that chain, and genuine constructors combined with a foreign `newTarget`. Construction-context identity for the latter must be measured, not inferred from the constructor, prototype or `instanceof`. A Host Promise merely assigned a VM prototype *after* allocation must remain unrelated Host work; the eager current implementation already ignores it. An alleged Host-forgery counterexample only establishes a defect when genuine V8 provenance and actual baseline event routing disagree.

The prepared baseline records ten actual Promise objects: ordinary VM, null-after-init, VM subclass with null chain, VM subclass with foreign chain, Host constructor/VM newTarget, VM constructor/Host newTarget, Host Promise assigned a VM prototype after allocation, VM subclass/proxy chain, genuine foreign VM, and disposed VM. It records actual `util.types.isPromise`, public-V8 sameRealm/creationGlobal, page event identities/order, process notifications and prototype-trap calls. Its explicit process observer makes unrelated failures observable instead of fatal only in that classification child. A separate child tests the unchanged sole-listener fatal Host path.

## Native policy must be calibrated first

Pinned Native `Env.promiseRejectCallback` uses `Context.fromIsolate` when V8 notifies rejection and late handler attachment. It queues rejected Promises on that current context and searches all contexts to withdraw a pre-report rejection. It does not visibly query the Promise creation context there. This source is an explanation candidate, not runtime evidence that creation-context attribution agrees or disagrees.

Eight actual Native observations therefore exercise main/frame construction, a foreign Promise with a main executor/rejector, main/foreign reject calls, changed subclass chains, late handling from a foreign function, and an actual removed frame. Both globals' actual event listeners preserve target, type, exact Promise identity, reason, trusted/cancelable flags and order. No expected realm is hardcoded. Timing and listener delivery differences remain visible. Host Promises cannot be injected into Native through ordinary page JS, so no Native claim is made for that counterexample.

## Proposed authority, conditional on the observations

For classification, first use genuine `types.isPromise`; proxies and thenables fail without property access. Use the existing binding's real GetCreationContext operations, not prototype or constructor names. A captured actual realm anchor, registered by trusted startup before authors, supplies the exact comparison authority. `creationGlobal(promise)` may index candidate records, but a possibly reusable public global proxy must never be the sole authority: every hit requires `sameRealm(promise, record.anchor)`.

Retain immutable per-context records, not one replaceable entry per proxy. Existing Node contexts and future reusable globals need distinct anchors even when a public proxy repeats. A possible index is WeakMap(actual creation-global proxy → weak record bucket), checked against real immutable context anchors. An anchor-keyed ephemeron registry can retain the record while its genuine context's captured intrinsic remains live. This retention/lifetime assumption requires an actual retained/null-prototype Promise and GC control before acceptance; a plain transient array key or a weak-only retired record is insufficient. If the current trusted realm registry cannot supply this lifetime, the design needs a context authority seam rather than silently forgetting ownership. No new public-V8 context token or build is proposed in this first gate.

Known retired/disposed ownership must remain recognizable. Such rejections are ignored by the current policy and must not become fatal Host failures. Disposal sets inactivity; it must not delete the only provenance tombstone. Unregistered or Host contexts must continue through the existing unrelated-Host branch. Existing module/utility/worker coverage must be enumerated honestly: installErrors currently registers actual main/frame Windows and standalone installed JSDOMs, not isolated utility worlds or worker contexts. This refactor must not silently expand those owners.

At first `unhandledRejection`, look up or create the private Promise state before dispatch, then preserve the existing writes: reason is recorded even for inactive owners; reported becomes true before authored `unhandledrejection` listeners run; only active records dispatch/forward. This matters when the listener immediately attaches a catch or disposes the page. `rejectionHandled` must only use existing state, must not infer/report a previously unseen rejection, and retains the existing late-null reason contract from createPromiseRejectionEvent. A Promise handled before Node's unhandled notification causes neither page event and needs no state. The Host listener multiplicity/fatal fallback, default prevention, genuine event factory, forwarding, recursion guard and callback/timer error paths remain unchanged.

Lazy state creation removes eager per-allocation prototype observation as a consequence of replacing the attribution mechanism. This is not authorization to disable ownership or merely omit tracking. It must first prove all baseline ownership and reporting semantics, immutable context adversarial cases, and disposed/Host failures. Do not ship rejected R3 or infer recovery under independent hooks.
