# Public Node callback and Promise interruption audit

This is static analysis only. Root, its native addon and its toolchain are unchanged. No callback-scope experiment or minimal Node observation below has run. The rejected R3 experiment remains immutable; the accepted narrow scheduler fix does not add a native checkpoint or claim Promise interruption recovery.

The exact Node 24.22.1 implementation was read from the public tag and saved in `node-public-callback-source/callback-v24.22.1.cc`; `source.json` records its URL and hash. The installed Node header documents `node::CallbackScope`, `node::MakeCallback` and `node::AsyncResource` as public APIs. Real Node resources and their actual async-context IDs must be used; no copied marker, private registry access or hook replacement is proposed.

`CallbackScope::~CallbackScope` marks its internal scope failed when its TryCatch caught an exception. `InternalMakeCallback` also calls MarkAsFailed when the actual V8 function call returns an empty MaybeLocal. Those are real C++ cleanup boundaries and are relevant to termination that skips JS finally blocks. However, the actual implementation still calls pop_async_context for the scope's own ID before returning on failed_. Its explicit clear_async_id_stack branch is conditional on the Environment stopping. A recoverable VM timeout is not evidence that the whole Environment stops. Therefore neither header comments nor MarkAsFailed alone establish that an abandoned nested Promise hook frame will be restored. An actual owned-child test is required; no private reset is an acceptable substitute.

The current addon performs a real isolate microtask checkpoint inside the selected Window's timed invocation. In R3, its finite behavior matched all seven actual Native objects. An infinite finished reaction then caused Node's async-hook stack corruption and exit 1. That measured failure must remain visible. Production errors.js enables an init-only PROMISE createHook independently of AsyncLocalStorage, so ALS-only minimal controls cannot establish the relevant hook behavior.

The next minimal public-JS plan has ten independent owned children: default VM/native checkpoint with ALS on and off; afterEvaluate VM with ALS on and off; nested afterEvaluate checkpoint; actual Host-produced Promise ownership; default/native checkpoint with init-only PROMISE hook; afterEvaluate with the same init-only hook; and two poison cleanup controls. These retain a 200 ms VM budget, 4 s child deadline and 45 s total administrative ceiling. Negative exits are observations, not failed cases silently converted to passes. `run-minimal-node-r2.py` is prepared and unrun.

The afterEvaluate ownership case explicitly resolves an actual VM Promise from a Host producer, samples its real queue before and after a Host tick, then performs a real owned VM entry. It does not create a fake VM result or force DOM readiness. Even if this interruption mode is safe, it would require genuine scoped jsdom Window creation and correct async-producer entry ownership. A global vm.createContext monkeypatch, a new unrelated VM for each callback, or a then-delayed finish event is not a valid implementation. Node Contextify contexts also need separate SourceTextModule acceptance checks; the older raw public-V8-context module-registry blocker is not assumed resolved by analogy.

If the minimal evidence does not settle the public callback-scope question, a separate tiny diagnostic addon can compare three real boundaries: the existing plain checkpoint, CallbackScope with an actual AsyncResource, and AsyncResource::MakeCallback of an actual native checkpoint function. It must use node.h/v8.h only, an actual captured Node Environment/context/resource/receiver, public IDs, and TryCatch/empty-return handling. It must run inside the same 200 ms VM deadline with an external child cap, then prove a later positive checkpoint and Host tick. Source, build and process hashes must be recorded in a new proposal directory. It must never access Node private fields or reset async IDs. This addon has not been written or built; no safety conclusion follows from the plan.

The poison diagnostic uses uncaughtExceptionMonitor, which records the real error and leaves Node's default uncaught behavior intact. It first completes the actual animation assertions with interception count zero, then compares teardown with the replacements retained versus restored. Only if the stacks show unrelated teardown calls may restoration be classified as proper test cleanup; genuine animation interception must still fail. The queue-only test already restores exact original descriptors after its assertions, and all three SDKs passed without late exceptions, but the specific late caller stacks are still unmeasured.
