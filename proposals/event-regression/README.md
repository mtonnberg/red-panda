## Concrete causes and fixes

First, the scalar/declaration CSSOM fixtures deliberately create JSDOM with no runScripts option. Those Windows genuinely use Host intrinsics, not a VM context. The new private Event installer required vm.isContext and threw during Window interface initialization, before any CSS declaration operation. `baseline-v1.txt` preserves the exact captureRealm → Event.install → installInterfaces → createWindow → JSDOM fixture stack. No CSS algorithm or test assertion was defective.

The correction accepts the actual no-runScripts Host originating Window (non-VM, self _globalObject, actual Host Object intrinsic) and constructs its public isTrusted getter in that real Host realm. Actual VM contexts keep the existing VM compilation path. No VM is invented and no Host value is relabeled by changing its prototype. The Host/VM getter contexts are measured directly with public V8 GetCreationContext before/after prototype=null. The same genuine private Event backing and strong receiver checks remain; no public implementation symbols are restored.

Second, early imported media/dialog helpers destructured the old utils.implForWrapper function before the private Event installer replaced the export. JavaScript retained that original symbol-based function; changing the canonical export could not update captured references. Those old readers returned undefined for actual new private Events. The full run explicitly reported media trusted(): undefined.isTrusted; the isolated dialog negative delivered no close event. Dynamic imports in CSS compatibility and static dialog import before dynamic Browser made the issue reproducible. Existing Event-private state and actual event flags were valid.

One stable owned-module resolver now consults the genuine Host-private Event WeakMap first, then the current canonical jsdom utility graph for nonEvents. Seventeen actual Event-consuming owned modules import this resolver rather than capturing an obsolete function. Original generated jsdom factory/utility export identities, backing records, receiver realms, Node/Window/File/etc behavior and real dispatch paths remain intact. No per-test bootstrap workaround, descriptor fake, trust-result substitution or CSS/assertion modification is included.

`backend-reader-audit.json` inventories all71 src modules containing implForWrapper, with exact original sites and actions. The17 switched modules are audio-core, animations, classic-scripts, cookie-store, dialogs, dom-events, errors, fonts, forms, indexeddb, input, media, mutations, performance, scheduler, storage-event and text-tracks. The remaining sites use the canonical utility object dynamically or operate on nonEvent backends. Existing third-party CJS captures were inspected: relevant helper captures operate on targets/Node implementations; generated private Event code already consults its real canonical utility object. No node_modules file or utility graph was replaced.

No assertions were changed to conceal a regression.
